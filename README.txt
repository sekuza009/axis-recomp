recomp - rebuilding AxisGL.exe function by function (PRIVATE test work; never ship)

Method: the original exe keeps running; rebuilt C versions of game functions live in recomp.dll. At start-up
recomp.dll compares each original against its rebuilt version on random inputs (results in recomp.log next to
the exe), then redirects the original to the rebuilt code (jmp at the function entry).
Set RECOMP_NOHOOK=1 to only compare.

Files
  recomp.c            rebuilt functions + comparison harness (add new functions here)
  build.bat           builds recomp.dll (zig cc, x86-windows-gnu; add -Wno-unused-label for the lifted code)
  lifted/*.c          generated by tools/lift.py (do not edit; re-run the lifter - commands in the batch notes)
  axisnet_recomp.c    copy of axisnet\axisnet.c + one block in DllMain: load recomp.dll from the game folder
  build_testexe.py    normal AxisGL patch chain into build\AxisGL.exe, embedding axisnet_recomp.dll
                      (build the DLL first: zig cc ... -I..\axisnet -o axisnet_recomp.dll axisnet_recomp.c + iv32 objs)
  test2.sh            temporarily installs build\AxisGL.exe + recomp.dll, plays a round-12 skirmish, restores the
                      installed exe (checked identical), removes recomp.dll, diffs Save\
  inject.c            old CreateRemoteThread loader - Windows Defender quarantines the built exe; not used

Readable source (src/, from batch 214 on): the goal is the game's code as organised, readable C that stays
bit-exact. src/ is its own translation unit (x87 maths, -mno-sse), linked into recomp.dll by build.sh (which now
replaces the single cc command). Conventions are in src/axis.h: the scene object is a struct generated from
src/scene.fields by tools/mkscene.py (every offset checked at compile time); game.h names the game's functions,
globals and imports by their original addresses; a call to another game function is an ordinary call that goes
through the original address (so the harness stubs still apply and the installed version runs); a rebuild is
defined as "void (name)(...)" so its own call macro does not expand there; float compares are written so NaN
takes the original's branch; ftol() is the original __ftol. recomp.c declares the src functions and its tests
call them directly. Pilot (6, all bit-exact first time): src/text/text_size.c (text_drawSized, hud_44ae10),
src/hud/hud_overlay.c (hud_4950a0, hud_drawFps, hud_4953d0), src/hud/hud_message_box.c (replay_drawMessage).

Lessons:
  - x87 compare flags: after fcom/fcomp, "C0 set" (test ah,1 non-zero) = less OR unordered -> write !(a >= b);
    "C0 clear" = ordered a >= b -> write (a >= b), NOT !(a < b) (that is also true for NaN). ViewVolume_add's
    outcodes differed on 11 of 3004 NaN inputs until this was fixed.
  - Test setups must not create states the original cannot survive either (a null list base with n > 0 crashed both;
    recomp.progress named the test).
  - clang turns (float)((long double)a * b) into an SSE mulss (exact for two floats), but with two NaNs mulss keeps the
    first operand and x87 fmul keeps the larger payload. Hold one factor in a volatile long double (collision_4803c0).
  - clang folds "(-x) * a + b" into "b - x * a", which flips the sign of a NaN result compared to the original's fchs
    first. Keep the negation in a volatile long double (match_4722e0); same for fld/fchs/fstp negates (SNaN -> QNaN).
  - Read constants from the binary, not the decompiler's rendering: the hue sliders clamp to 0x43b38000 = 359.0, not 360.
  - Ghidra's pointer arithmetic on typed globals hides strides: "&DAT + i * 0x20" on an int table is i << 7 bytes.
  - x87 "fcomp; test ah, 0x40" (equality) is also true for NaN; store float parameters the original copies with
    mov as raw dwords (x87 loads would quiet signalling NaNs).
  - x87 "fcomp; test ah, 1" is also true for NaN: write "if (!(x >= 0))", not "if (x < 0)".
  - movsx + cmp with 0xa5 as an int is never true for a signed byte (save_cryptRecord's key never wraps).
  - MSVC 6 x87 code keeps products in 80-bit precision; use long double intermediates and round to float exactly where
    the original stores (fstp dword) - read the disassembly, the decompiler hides these points.
  - Return width: check what the original writes (mov eax, n vs mov al, n). Ghidra typed 0x4326f0 as char; the C
    version returned only AL, the caller stored all of EAX and the game crashed. Compare full registers in tests.
